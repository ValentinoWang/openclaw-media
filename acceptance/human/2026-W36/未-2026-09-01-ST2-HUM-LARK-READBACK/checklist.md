## H-01

- 验收问题：组织成员编辑真实飞书 Docx 后，能否在 Web 镜像中理解新版读回并确认 Web 没有组织正文编辑入口？
- 必须人工判断的原因：真实飞书版本、真实保存和 Web 镜像之间的回读关系不能由本地 mock 自证。
- 闭环名称：飞书编辑后组织只读镜像回读。
- 验收角色：具有受控测试 Docx 编辑权限的真实组织成员。
- 进入方式：先完成组织登录，再在飞书客户端打开已绑定的受控测试 Docx。
- 要做的事：编辑并保存飞书正文，刷新对应 Web 成果页，比较远端版本和更新时间。
- 前置条件：组织扫码链路已通过；受控真实 Docx、Binding 和 Web 组织镜像可用；不得使用生产敏感内容。
- 验收步骤：
  1. 在飞书客户端修改同一篇受控 Docx 的正文并保存。
  2. 回到 Web 组织成果页并刷新。
  3. 确认镜像显示新的远端版本号和修改时间，且页面只有只读呈现和“在飞书中打开”路径。
- 预期观察：新的远端版本与更新时间可见，Web 不提供绕过飞书权威的编辑入口。
- 副作用确认：仅受控测试 Docx 被修改；没有创建额外文档或更改 Binding。
- 失败表现：版本不变、读回失败、镜像内容不一致或出现 Web 编辑入口时，记录阻塞性结果。
- 判断标准：验收人能从可见信息确认本次飞书保存被镜像读回，并清楚区分组织正文的唯一编辑权威。
- 预计时长：15 分钟。
- 是否阻塞发布：是
