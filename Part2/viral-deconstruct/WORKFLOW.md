# Part2 工作流：拆解 / 再创作

## 触发规则

- 只有输入包含 `【拆解】` 才执行爆款拆解。
- 只有输入包含 `【再创作】` 才基于拆解和用户想法创建新的飞书云文档。
- 不带标签：不拆解、不再创作，只走普通素材整理。

## 写入反馈规则

每次写入飞书多维表格或创建飞书云文档后，必须反馈给用户：

1. 多维表格链接 + record_id。
2. 云文档链接 + document_id。
3. 本地 JSON 备份路径（如有）。
4. 附件保存情况：视频/图片/原音频是否上传；超过 20MB 的文件说明只保留本地路径或后续走分片上传。

- 免费版总云空间公开信息常见口径：认证前约 15GB，认证后约 100GB；以飞书管理后台实际显示为准。

## 2026-05 更新

- 默认飞书知识库父节点：`QA0BwF5Yji0EvfkmOiOcBuMQnze`。
- 【拆解】不仅写多维表格，也创建「拆解文档」。
- 【再创作】创建「再创作文档」。
- 文档必须用结构化 block 写入：标题 2 + 段落/列表，不允许再把 Markdown 标题作为纯文本整块塞入。
- 每次完成必须反馈：多维表格 record_id、拆解文档链接、再创作文档链接、JSON 备份路径、附件/音频保存情况。

## 文档格式强约束

- 飞书文档不使用 Markdown 表格冒充表格；分镜必须使用飞书 Docx Table Block。
- 分镜表字段：`画面图`、`画面描述`、`字幕`、`口播`、`运镜`。
- `画面图` 单元格不能写本地路径、URL 或“见附件”冒充图片；有图片 token 时必须插入 Image Block。
- 字段语义固定：
  - `visual`/`画面描述`：只写画面、动作、场景、构图、道具等视觉描述。
  - `subtitle`/`字幕`：拆解时只写真正在原视频里识别/抓取到的字幕；再创作时只有确实需要上屏文字才写。不能用来放画面描述，不能默认每个镜头都加。
  - `voiceover`/`口播`：拆解时只写真识别到的口播；再创作时写计划口播。没有就留空。


## 文档排版最终约定

- 不再使用 Markdown 表格；飞书文档里 Markdown 表格不会渲染成真表格，手机端观感差。
- 分镜/图文脚本改为“卡片式”：
  - `镜头 1｜0-1.5s` / `第 1 页｜xxx` 作为三级标题。
  - 下方分别写：画面、字幕/口播、运镜、道具、剪辑要点。
- 不额外生成本地备份作为用户反馈项；如脚本内部需要调试文件，不主动反馈给用户。


## 素材分析与清理规则

- 【拆解】必须先用 Part1 下载原视频/原图文，再基于下载素材分析；禁止只看链接猜测。
- 视频素材进入 OpenAI 前先抽关键帧作为视觉证据；分析完成后删除抽帧中间文件。
- 视频关键帧会复制为文档视觉资产并分配稳定 ID：`frame_001`、`frame_002`。
- 图文原图会分配稳定 ID：`image_001`、`image_002`。
- LLM 输出的 `video_storyboard` / `image_post_script` 必须包含合法 `evidence_asset_id`；非法 ID 触发重试，仍失败则中止。
- `VIDEO_UNDERSTANDING_PROVIDER` 支持 `gpt_frames` / `qwen_omni` / `hybrid`。
- Qwen-Omni 只生成 `native_video_observation`，最终拆解 JSON 仍由主模型基于证据包输出。
- `hybrid` 模式下 Qwen-Omni 失败可回退到本地抽帧；主模型失败不得写文档/写表。
- 保留最终需要的原视频、原音频、原图；分镜示意图只在用户明确要求生成时保留。
- 【再创作】必须基于【拆解】结构化结果，尤其是 `video_storyboard`，不得跳过拆解直接创作。
- 再创作文档默认不调用 gpt-image-2 生成镜头示意图，避免消耗 Codex 图片额度；只有用户明确说“生成示意图 / 生成分镜图 / 带画面图 / image2 / gpt-image-2”时才生成并插入文档表格。

## 最新用户规则整理

- 分流必须是代码规则，不靠 prompt/agent 启发式：
  - 仅【拆解】：下载原作品 -> 基于本地视频/图片分析 -> 写多维表格 + 拆解文档。
  - 【拆解】+【再创作】：先完成拆解，再基于拆解结果再创作 -> 写再创作文档。
  - 仅【再创作】无【拆解】：拒绝并提示“必须先提供【拆解】或已有拆解结果”。
  - 无标签：普通素材整理，不进入拆解/再创作。
- 不能只看抖音链接、标题、文案猜；代码必须检查已下载素材/抽帧/图片证据存在，否则中止。
- 视频：下载原视频；抽关键帧用于模型分析；抽帧中间文件分析后删除；原视频保留到多维表格“原文件”附件字段；原音频单独上传到“原音频”附件字段。
- 图文：上传原图片到“原文件”附件字段；文案已收集，不要在文档中重复堆一遍；如有音频才单独上传音频附件。
- 多维表格：
  - “封面图/前五秒”只放封面图或前五秒预览。
  - 新增“原文件”附件字段，保留完整原作品（视频或原图）。
  - 新增/使用“原音频”附件字段，单独保留音频。
- 分镜文档：使用飞书真正表格承接，字段：画面图、画面描述、字幕、口播、运镜。字段允许空白。
  - `画面描述` 承接 `visual`，不是 `subtitle`。
  - 拆解文档中 `字幕` / `口播` 必须来自真实识别/抓取；没有就空，不补“假设复刻字幕”。
  - 再创作文档中 `字幕` 是可选计划上屏文字，`口播` 是可选计划说出口的声音；两者都不是必填内容，图文脚本和视频脚本二选一。
  - 拆解文档的画面图来自上传后的关键帧/原图 `file_token`，插入 `block_type=27` 图片块。
  - 未明确要求 image2 时，再创作文档的“画面图”允许留空，只写画面描述、运镜、剪辑要点等文本执行稿。
  - 明确要求 image2 时，生成的示意图放在文档分镜表格的“画面图”，不应只塞进多维表格附件。
- 每次写入飞书多维表格或飞书云文档，只需要反馈对应链接；不需要反馈本地备份路径。

## 入口媒体类型识别

- Part2 拿到作品后，第一步必须通过 Part1 `resolve_media` 的返回值判断 `media_type` 和实际产物：
  - `video_path` 存在 => 视频作品。
  - `image_paths` 存在且无 `video_path` => 图文作品。
  - 两者都不存在 => 中止，不能拆解。
- 后续流程按媒体类型分支：
  - 视频：抽关键帧 + 提取原音频 + 原视频入“原文件”。
  - 图文：原图片入“原文件”；不重复堆文案；通常无原音频。

## 强制执行顺序（不可跳过）

每次收到带【拆解】的作品，必须重新走一遍干净流程，不复用旧文档/旧 record 冒充完成：

1. 解析链接并调用 Part1 下载原作品。
2. 判断媒体类型：video_path => 视频；image_paths 且无 video_path => 图文；两者都无 => 中止。
3. 视频抽帧/图文读取原图，基于真实素材完成拆解。
4. 先创建【拆解】云文档，并校验链接可访问。
5. 如果有【再创作】，必须基于第 3 步拆解结果创建【再创作】云文档，并校验链接可访问。
6. 只有在文档校验通过后，才写多维表格。
7. 多维表格优先写入顺序：
   - 原作品基础信息
   - 封面图/前五秒预览
   - 原文件附件
   - 原音频附件
   - 拆解文档链接
   - 再创作文档链接
   - 总结 / 爆点拆解 / 爆点迁移 / 核心价值等摘要字段
8. 写表前必须检查目标 record 是否存在；如果不存在，新建 record；不能假装更新成功。
9. 若用户要求“重新来”，默认新建干净文档和干净记录，不沿用旧脏数据。


## 多维表格字段边界（强约束）

多维表格只保存索引、素材附件、核心摘要和文档链接，不保存长脚本。

不得写入/新增这些字段：
- 可复制发布稿
- 分镜脚本
- 图文脚本

这些内容只写入对应飞书云文档。

多维表格必须尽量给出：
- 原标题
- 参考链接
- 平台
- 总结
- 赛道/标签
- 封面图/前五秒
- 原文件
- 原音频
- 热榜字段
- 核心数据
- 爆点拆解
- 爆点迁移
- 吸睛元素
- 核心价值
- 痛点/爽点
- 发布时间
- 高赞评论
- 目标受众
- 拆解文档
- 再创作文档

## 文档分镜表图片规则

- 再创作文档默认不生成 gpt-image-2 示意图；视频分镜表的「画面图」可以留空。
- 只有用户明确要求 image2 / 示意图 / 分镜图 / 带画面图时，才调用 gpt-image-2 并把示意图插入「画面图」。
- 明确要求生成图片时，画面图不应用路径/URL 纯文字替代；若图片写入失败，必须明确失败，不假装完成。
- 飞书 Docx 表格有行数/单元格限制；长分镜必须自动拆成多个真表格继续写，不能退回 Markdown 表格。
