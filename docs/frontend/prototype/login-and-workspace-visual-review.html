01

先说方法和一个限制

线上站我没能直接打开。这个会话的网络策略把 106.52.146.37 挡在允许列表之外，返回 403 Host not in allowlist。所以我换了等价的做法：直接跑仓库源码——openclaw-bot-center 的 media 构建入口，本地 Vite 起服务，用 Chromium 按 1440×900 实拍，并对关键尺寸做了程序化测量。页面产物和线上是同一套源码，视觉结论可以直接用；只有真实业务数据填充后的密度需要你们再校一眼。

覆盖到的：登录页三个状态（选身份 / 个人密码 / 组织扫码）、注册、验证、找回、重置，以及登录后的个人云端工作区、组织工作区、账号与赛道、平台总览、用户与准入、计费运营。

参考侧读的是 mediaclaw-web/src/styles.css 全量 270 行，提炼出下面第 3 节那套手法。

02

诊断：问题不在配色，在密度和层级

配色其实是对的——mediaDesignTokens.css 已经把参考站的纸绿体系搬过来了，连 #1a9b68 都一致。真正拉开差距的是三件事：字阶太平、留白失控、颜色资产闲置。

D1P0

选完身份，登录按钮掉到折线以下

身份选择区选中后不折叠，仍占满原尺寸，把表单整体下推。1440×900 下文档高度从 900 涨到 1031px——用户必须滚动才能看到密码框和登录按钮。这是登录页最贵的一次转化损失。

docHeight 900 → 1031px · viewport 900px
D2P0

输入框 646px，提交按钮 60px

表单元素的宽度和它的重要性完全倒挂。646px 的输入框远超舒适录入宽度（360–420px），而最该被点的「登录」只有 60px。视线落点被稀释，页面读起来像一张表单草稿。

#identifier 646px · #submit 60px
D3P1

首屏 54% 是空的

个人云端工作区里，内容在 418px 处就结束了，视口以下 482px 全是背景色。右侧「云端交付与预览」甚至是一个连空状态都没有的纯白盒子。

内容终点 418px · 空白 482px / 900px
D4P1

252px 深绿侧栏，只装了 1 个导航项

个人壳层的侧边栏是整屏视觉最重的色块，却只有「个人云端成果」一条。深色面积和信息量严重不匹配，把用户的注意力吸到了一个什么都没有的地方。

sidebar 252px · navItems 1
D5P1

标题字阶从头到尾是 28px

登录页 h1、工作台页标题、卡片标题挤在很窄的字号区间里，字重 700、字距接近 0。参考站同层级是 clamp(42px, 5.1vw, 72px)、字重 800、字距 -.065em——那个紧收的负字距正是它「看起来贵」的主要来源。

现状 28px / 700 / -0.98px
D6P1

六组 accent 定义了，但界面上看不见

token 里 studio / campaign / business / desk / agent / archive 六组业务色，加上小红书、抖音、微信、B 站四组平台品牌色，全都躺着没用。整个产品目前只有一个绿色相，页面之间缺少辨识度。

--mg-accent-* × 6 · --mg-brand-* × 4
D7P2

空状态没有出口

「暂无云端成果」只给了一个小图标和两行灰字，没有主 CTA。新用户第一次进来看到的就是这个——它应该是引导页，不是通知页。

D8P2

页头操作没有主次

「服务端已解析 / 查看任务状态 / 刷新」三个元素视觉权重相同，都是描边小按钮。哪个是主操作、哪个只是状态标识，读不出来。

03

参考站真正在做的十件事

把 MediaClaw-Web 的样式拆开，让它「好看」的其实是一组可以逐条搬运的具体手法，不是某个说不清的气质。

先说一句要紧的：下面十条里，负字距、按钮抬升、药丸、accent 渐变、毛玻璃这五条，mediaPrimitives.css 里已经实现过一遍了。它们没出现在界面上，唯一的原因是没有页面在用那些原语——详见第 6 节。

  • 大字号 + 负字距。显示层 clamp() 到 42–72px，字重 800，letter-spacing: -.065em。中文标题收到 -.04em 左右即可，再紧会粘连。
  • 彩色卡片家族。mint / lavender / peach / blue / yellow / green 六种淡色底，替代「白底 + 1px 边框」的统一处理。同一屏里靠色相区分卡片语义。
  • 有机形状垫底。border-radius: 48% 52% 43% 57% / 46% 43% 57% 54% 加渐变、旋转 −8°、透明度 .88，垫在主视觉后面。
  • 产品窗口模型。三个交通灯圆点 + 标题栏 + 轻微旋转（1.6–2.2°）+ 大阴影。把界面截图变成有质感的对象。
  • 浮动注释卡。绝对定位压在窗口边缘，图标 + 一行加粗结论 + 一行说明，把注意力钉到具体功能上。
  • 色块位移垫底。::after 一块 mint 实色偏移到视觉物右下角，成本极低、效果立竿见影。
  • 药丸标签页。border-radius: 999px，激活态用 ink 底 + paper 字——高对比、不靠边框。
  • 按钮抬升。:hover { transform: translateY(-2px) } 配阴影加深。参考站给所有 .button 都加了，交互手感的一半来自这一行。
  • 半透明吸顶。backdrop-filter: blur(18px) + color-mix 背景，滚动时头部有层次而不遮挡。
  • 用 color-mix 分层。中间色一律由现有 token 混出来，而不是再硬编码一个新色值。这是它 270 行样式能撑住整站的原因。

06

原语其实已经有了

这是这次评审最重要的一个发现，也是它改变了我原本那份清单的组织方式。mediaPrimitives.css 里已经躺着 28 个 .mg-* 原语，ui/ 下已经有 Metric、SurfaceState、SearchBox 这些收敛过的组件。缺的不是设计系统，是采用率。

这些资产的来历是 docs/frontend/openclaw-media-ui-beautification.md（2026-08-26 那轮，改动 34 个文件）。它的 Layer 0 大获成功，Layer 2 建成即停——两层的采用率相差 150 倍。

08

登录链路 P1 / P2 规格

这一节是登录链路的完整交互规格：P1 只负责选身份，P2 先查可用会话、有则一键继续、无则回退到原有登录方式，两条分支完全对称。它细化并部分修正了第 4 节的登录页示意图——修正点见下方「与示意图的差异」。

流程

P1 选择身份
├─ 个人创作者
│  └─ P2 查询个人会话
│     ├─ 有效：显示脱敏账号 → 继续进入
│     └─ 无效：显示用户名 / 邮箱 + 密码登录
└─ 组织成员
   └─ P2 查询组织会话
      ├─ 有效：显示组织身份 → 继续进入
      └─ 无效：生成 Feishu 二维码 / 授权按钮

P1 绝不因为浏览器有 Cookie 就自动跳转，必须等用户明确点击左卡或右卡后才进入对应 P2。这条要写进验收，否则「有会话就直接进」会悄悄回归。

好消息：骨架已经在了

现有 media.login.html 已经是 P1 / P2 结构——.identity-choice 带 role="tablist"、两个按钮带 role="tab" 和 aria-controls，两个 .auth-panel 是 role="tabpanel" 且默认 hidden，每个面板都有「返回选择」。一期要加的是「入口状态区」这一层，不是重做导航。二维码目前也还没有提前生成的逻辑，改成延迟生成的成本很低。

与示意图的差异，以及一处硬冲突

第 4 节示意图把身份选择收成了表单顶部的药丸分段控件；本规格要求保留两张卡、选中高亮、P2 在下方展开。以规格为准——卡片形态承载得下图标、说明和状态，分段控件承载不下。但这样一来，D1（登录按钮掉折线）就回来了：

状态（1440×900 实测）P1 占用P2 占用文档高是否出折线
P1 未选286px—900px一屏内
个人 · 回退到密码登录286px470px1031px超 131px
组织 · 回退到 Feishu 授权286px529px1090px超 190px

解法：P1 选中后压缩，而不是消失。选中卡收成一行精简态（图标 + 身份名 + 高亮边），另一选项降级为一句「改用组织成员登录」的切换链接。P1 仍在上方、仍高亮、仍可一键切换，完全满足规格，但高度从 286px 降到约 72px，释放 214px：

  • 个人回退态：1031 − 214 = 817px ✓ 一屏内
  • 组织回退态：1090 − 214 = 876px ✓ 一屏内
  • 命中有效会话时 P2 只有脱敏账号 + 继续进入，更短，完全无压力

示意图里其余的登录页改动不受影响、继续有效：左叙事右表单的双栏、表单列收窄到 400px 以内、主按钮通栏、以及第 7 节的 token 收敛。

阶段内容是否需要改认证合同

当前系统只有一个 HttpOnly openclaw_session Cookie，现行认证合同明确不提供「记住我」。所以一期的「保存状态」只能定义为「当前浏览器已有的有效会话」，不能用 localStorage 假装实现多账号保存——真正的多账号留到认证合同确认后的三期。

一期实现矩阵

下面用仓库相对路径，对应你给的那几个绝对路径。

层文件改什么
前端openclaw-bot-center/media.login.html两个 P2 面板各增加「可用登录状态」区域、继续进入按钮、使用其他账号入口，以及加载 / 失效状态

前端有一条约束要守住：不修改现有 parseMediaSessionEnvelope 的严格响应结构。入口状态走新接口，不往严格的 /openclaw/media/api/session 里塞字段。

接口

GET /openclaw/auth/entry-state?mode=personal
GET /openclaw/auth/entry-state?mode=organization
{
  "schemaVersion": "media_auth_entry_state_v1",
  "mode": "personal",
  "state": "matched",
  "entry": {
    "entryId": "current",
    "displayLabel": "当前个人工作区",
    "maskedIdentity": "v***@example.com",
    "expiresAt": "..."
  },
  "fallback": "password"
}

state 至少覆盖 matched、none、expired、mismatched。响应只返回脱敏信息——不返回密码、Feishu Token、原始租户 ID，也不返回任何可直接使用的会话凭据。

一期点击「继续进入」时，直接重新读取并校验当前会话后跳转即可。二期 / 三期要切换工作区或选择其他保存项，再增加 POST /openclaw/auth/entry/activate——该接口必须要求同源校验、X-OpenClaw-CSRF、必要时的 Idempotency-Key，并由服务端重新解析工作区和成员关系后轮换 openclaw_session。

安全边界

  • 前端传入的 mode 只能表达用户意图，不能决定 tenantId、workspaceMode 或 bodyAuthority。
  • 个人只能匹配 personal_web / internal。
  • 组织只能匹配 organization_lark / lark，且 Feishu binding、成员关系、工作区三者都必须有效。
  • 失效、撤销、停用、跨租户状态必须统一回退，不泄露账号是否存在。
  • 继续沿用 HttpOnly / Secure / SameSite 与当前会话 TTL，本轮不加「记住我」。
  • 不使用 localStorage、sessionStorage 或 document.cookie 保存登录状态。
  • OAuth 的 next 必须由服务端校验并绑定到 OAuth state，不能直接信任回调参数。

验收

  • P1 点左卡进个人 P2、点右卡进组织 P2；有 Cookie 也不自动跳转。
  • 命中有效会话时显示继续进入，且个人不请求 Feishu、组织不立即请求二维码。
  • 无会话、过期会话、错模式会话都正确回退到原登录方式。
  • 返回、刷新、浏览器前进后退、?mode=… 深链接，状态一致。
  • 个人登录成功、组织 OAuth 成功后均正确跳转到安全的 next。
  • 重复点击、网络超时、二维码刷新、查询期间会话过期，均不产生错误跳转。
  • 桌面端、移动端、纯键盘操作都能完成 P1 → P2。
  • 跑 npm run qa:media-login-contract、定向认证 / 工作区测试、npm run build:media，以及 Playwright 的 P1 → P2 流程。

证据要分层：静态检查、单元测试、隔离 HTTP、Playwright、真实部署读回各自独立留证，不能用本地测试代替生产验收。这一点尤其要紧——我这轮的截图和量数全部来自本地渲染，线上 106.52.146.37 在本会话不可达（见第 1 节），所以上线前必须补一次真实部署读回。

10

两件顺带发现的事

一、11 页的 ordinary IA 可能已经进不去了。mediaRoleIa.ts 里的 ordinaryMediaNav 有 11 项（总览、素材与灵感、选题与决策、创作与交付、发布准备、复盘增长…），但按 mediaWebApi.ts 里的会话 schema，workspaceMode 只有 personal_web 和 organization_lark 两种取值，而 MediaApp.tsx 的 ordinaryRoute() 要求这两个判定同时为假才渲染。也就是说合法会话下这 11 个页面全都会被重定向走。这些页面的样式文件加起来 20 多万字符，如果确实是历史 IA，值得确认一下是否还要跟着这轮改；如果是我读漏了某条服务端下发路径，那更要确认——因为它决定了这轮视觉改造的工作量大头在哪。

二、字体在弱网下会静默回退。DM Sans 和 Noto Sans SC 走 media="print" onload 的非阻塞加载，这个处理是对的。但我在离线环境实拍时字体全部回退到了系统字重，负字距和 800 字重的效果会跟着丢失。建议 font-family 的回退栈里把 'PingFang SC' 提前，并且不要让视觉效果只依赖 800 这一档字重。
