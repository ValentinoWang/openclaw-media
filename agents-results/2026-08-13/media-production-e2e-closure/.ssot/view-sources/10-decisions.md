## 2. 推荐的唯一开发顺序

### 2.1 业务顺序

1. 现行飞书扫码登录、账号密码登录、飞书账号关联和租户角色会话已经写入并锁定为第 2 版认证合同。
2. D6 第 1 版冻结素材解析矩阵，前后端必须消费字节一致副本。
3. 以当前生产前端和后端源码为基线，分别合并 C2 任务闭环并实现素材解析前后端闭环。
4. 前端合并与后端合并都通过后，汇合成唯一、不可变、可核验的候选。
5. 在该候选上完成本地认证浏览器闭环；真实生产身份和生产浏览器证据不再提前阻塞候选构建。
6. 候选通过静态发布验证后，才允许在明确授权下发布；随后使用真实质量验收身份完成生产端到端验收和独立终验。

### 2.2 工程拓扑

```text
A1 当前生产基线 + B1 第 2 版认证合同 + C2 已接受任务实现 + D6 素材解析矩阵
                         │
             ┌───────────┴───────────┐
             ↓                       ↓
   C3 前端合并与提示         C4 后端解析与失败关闭
             └───────────┬───────────┘
                         ↓
                  C5 唯一候选汇合
                         ↓
                  C1 本地认证闭环
                         ↓
              DA 静态发布验证
                         ↓
              DB 生产端到端验收
                         ↓
              DC 独立终验与发布决定
```

该顺序避免两个错误循环：一是用旧发布覆盖现行飞书登录能力；二是要求“部署前先提供生产浏览器证据”。C1 证明候选本身正确，生产端到端验收（DB）再证明真实生产身份、真实发布和外部系统链路正确。

## 3. OP01：长期生产验收使用什么身份？

### 3.1 现在发生了什么

生产后端、飞书和数据库读回已在特定运行中通过，但当次认证浏览器截图因原质量验收账号失效而没有补齐，部分页面交互也仍未收尾。现行生产又新增飞书扫码登录和飞书账号关联，继续临时借用历史账号将使角色、租户、账号关联、凭据有效期和证据归属无法稳定复现。

### 3.2 已批准方案

| 项目 | 已批准结论 |
| --- | --- |
| 决策状态 | 已采用推荐方案；已接受、已关闭 |
| 正式决定 | 建立独立质量验收租户；普通用户与管理员使用两个相互分离、可续期、最小权限的身份 |
| 决策责任人 | 用户 |
| 长期运行责任人 | 安全负责人 |
| 本决定不代表 | 两个身份已经创建、当前有效，或真实登录验收已经完成 |

### 3.3 为什么采用该方案

独立质量验收租户可以隔离真实客户数据；两个身份可以分别证明普通用户权限与管理员权限；统一续期和撤销可以让生产验收长期复现。证据只保存脱敏后的稳定引用，不保存密码、令牌、浏览器会话或私人正文。

### 3.4 开发与生产验收分工

| 阶段 | 必须证明 | 不要求 |
| --- | --- | --- |
| B1 第 2 版合同 | 飞书扫码和账号密码登录并存；飞书账号关联；租户角色会话；未关联、跨租户和权限不足时失败关闭 | 不要求真实生产账号或生产截图 |
| C1 本地候选闭环 | 唯一候选在桌面端和移动端完成登录、退出、会话失效与恢复、角色拒绝和错误状态 | 不把本地身份写成生产身份 |
| DB 生产验收 | 两个真实质量验收身份、当前发布身份、当次桌面端和移动端浏览器证据、角色隔离及恢复 | 不允许复用历史截图替代当次证据 |

### 3.5 未采用方案

| 未采用方案 | 原因 |
| --- | --- |
| 继续临时借用历史账号 | 账号可能随时失效，角色和租户关系无法长期复现 |
| 一个账号同时承担普通用户和管理员 | 无法证明角色隔离，也无法形成两套独立认证证据 |
| 直接使用真实客户账号 | 扩大隐私和凭据风险，不适合作为可重复的验收资产 |

## 5. OP03：两项代表能力如何绑定客户自有账号？

### 5.1 业务对象边界

| 对象 | 含义 | 是否可以用于任务归属 |
| --- | --- | --- |
| 外部博主 | 用于研究、跟踪或内容分析的外部主体 | 否，不能据此推断客户拥有或获授权运营该账号 |
| 客户自有账号 | 客户实际拥有或获授权运营的平台账号 | 是，但必须存在正式的用户关系记录 |
| 账号文字 | 页面提交的平台名称和账号名称 | 只能用于查找，不能以文字相同直接创建或抢占归属 |

### 5.2 已批准方案

| 项目 | 已批准结论 |
| --- | --- |
| 决策状态 | 已采用推荐方案；已接受、已关闭 |
| 正式决定 | 创作咨询和自媒体创作在创建任务时都必须提供平台与客户自有账号；系统按租户、认证用户、规范化平台和规范化账号精确唯一绑定 |
| 完成条件 | 只能命中预先存在的正式用户关系；缺失、多义、跨租户、跨用户或冲突时必须在入队前拒绝 |
| 本决定不代表 | C2 已经合并进当前生产基线，或真实生产绑定已经验收 |

两条代表链都必须证明“谁以哪个客户账号发起了本次任务”。任务创建只能查找预先存在的正式关系，不能在请求时创建账号所有权。页面和接口必须执行相同校验，避免产生猜测、多义关系、首次请求者抢占归属或无法结算的悬空任务。

### 5.3 两项能力的输入与拒绝规则

| 代表能力 | 创建任务时必填 | 唯一绑定依据 | 不满足时 |
| --- | --- | --- | --- |
| 创作咨询（`selfmedia_creation_consultation`） | 问题、平台、客户自有账号 | 当前租户、当前认证用户、规范化平台、规范化账号，以及预先存在的正式用户关系 | 入队前拒绝，不创建任务 |
| 自媒体创作（`selfmedia_creation`） | 原有必填内容、平台、客户自有账号 | 当前租户、当前认证用户、规范化平台、规范化账号，以及预先存在的正式用户关系 | 入队前拒绝，不创建任务 |

其他自媒体能力保持现有输入要求，本决定不把客户账号约束无条件扩大到所有能力。

### 5.4 未采用方案

| 未采用方案 | 原因 |
| --- | --- |
| 只让自媒体创作强制绑定账号 | 只读咨询链仍无法证明认证用户和客户账号的唯一归属 |
| 两项能力继续允许省略账号 | 后端必须猜测或延迟失败，破坏失败关闭和收据身份一致性 |
| 所有自媒体能力一律强制账号绑定 | 无必要地改变无账号语义能力的公开接口，扩大回归范围 |
| 由任务请求临时创建归属 | 会产生首次请求者抢占账号归属的风险，不能替代正式用户关系 |

## 6. OP04：素材解析如何避免静默缺字段？

### 6.1 已批准方案

| 项目 | 已批准结论 |
| --- | --- |
| 决策状态 | 已采用推荐方案；已接受、已关闭 |
| 正式决定 | 以 9 个平台乘 6 种素材类型形成 54 个唯一组合；每项冻结解析方式、解析器版本、必填输出、中文失败提示、人工补充字段和下一步动作 |
| 完成条件 | 只有自动解析必填输出完整，或用户完成人工补充并重新校验，任务才可入队 |
| 失败政策 | 不支持、解析器不可用、解析异常、输出不完整、类型与文件不符、缺原文或缺附件都必须在入队前返回结构化错误 |
| 本决定不代表 | 图片、音频、视频、PDF 已经具备自动解析能力，也不代表真实生产附件验收已经通过 |

### 6.2 自动与人工边界

| 素材类型 | 平台 | 解析方式 | 失败后处理 |
| --- | --- | --- | --- |
| 文本 | 全部 9 个平台 | UTF-8 或 Markdown 自动解析 | 文本为空或无有效输出时显示原因，要求补充素材摘要 |
| 链接 | 微信 | 使用现有微信文章解析器 | 链接不可访问、异常或标题正文不完整时进入人工补充 |
| 链接 | 抖音、小红书 | 仅在现有内容流服务返回完整必填输出时自动完成 | 服务不可用、异常或字段不完整时进入人工补充 |
| 链接 | 快手、哔哩哔哩、微博、知乎、普通网页、未知平台 | 当前人工补充 | 明确说明未接入自动解析，要求补充标题、正文摘要和用途 |
| 图片、音频、视频、PDF | 全部 9 个平台 | 当前人工补充 | 明确说明不支持自动解析，并按类型要求补充关键内容和用途 |

完整 54 组合以素材解析覆盖合同（`contracts/material-parsing-coverage-v1.json`）为唯一业务合同；前端和后端只保留字节一致副本，不得各自维护另一套默认支持规则。

### 6.3 状态与入队规则

待处理（`pending`）、处理中（`processing`）、待人工补充（`pending_manual`）和失败（`failed`）都不是完成状态。只有自动完成（`completed_auto`）和人工复验完成（`completed_manual`）可以创建任务。人工补充沿用备注字段（`remark`），但填写本身不是完成：系统必须结合原始素材重新校验，再标记为人工复验完成。最终解析结果写入任务调用记录并保留原始输入，不能覆盖用户素材。
