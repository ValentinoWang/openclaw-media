## 实施要求

1. 先验证全部固定身份，并确认活动链接仍指向固定旧发布、新发布目录不存在、没有遗留 `/tmp/media-e2e-b4.*`。若这是监督器唯一允许的 L3 重试，且 Luna 已创建新发布，则只有在新发布清单、协调身份、来源元数据和不可变属性全部精确匹配本合同后才可继续恢复与验收；否则停止。
2. 使用 `mktemp -d /tmp/media-e2e-b4.XXXXXX` 创建隔离目录，从基础源快照复制文件，排除 `.git`、`node_modules` 和 `dist-media`。只读复用基础源 `node_modules`；不得在基础源内安装依赖或产生构建输出。
3. 只在隔离副本中修改前述 8 个候选源码和门禁文件。用户可见的“赛道与博主”统一为“账号与赛道”；个人 Web 的 `track` 任务层标签改为“账号与赛道”；机构飞书的“赛道管理”保持不变。其他“内容赛道”“赛道列表”等领域术语不做无关改名。
4. 强化 `checkMediaReleaseLabels.ts`：构建产物必须包含当前 16 个导航标签，并按生产门禁的精确双引号、单引号、反引号或 HTML 文本语义拒绝 6 个退役标签。不能删除或弱化现有计费、平台图标或其他断言。
5. 依次运行 `npm run qa:media-role-ia`、`npx tsx scripts/qa/checkMediaLanguageCatalog.ts` 和 `npm run build:media`。构建入口必须使用 `vite.media.config.ts`，所有入口资源必须使用 `/openclaw/media/` 前缀。
6. 构建后确认“账号与赛道”存在；6 个退役精确标签不存在；`index.html`、`login.html`、`register.html` 和哈希资源完整。
7. 在 `dist-media` 生成 `.source-snapshot.json` 与 `.source-to-artifact.json`。前者使用 `openclaw-media-source-snapshot-v1`，记录基础提交、基础状态摘要、固定输入文件清单摘要、补丁后 8 个文件摘要、构建命令、构建时间和新旧前后端发布身份。后者使用 `openclaw-media-source-to-artifact-v1`，记录前端发布、后端发布、构建命令、产物文件清单摘要和必须执行的旧发布回退计划。不得包含秘密或退役标签文本。
8. 使用以下唯一部署命令创建新发布：

   ```bash
   sudo -n /usr/local/sbin/deploy-openclaw-media-locked \
     DIST_MEDIA \
     /home/ubuntu/.openclaw/releases/openclaw-tag-router-media-tenant-20260811T201753CST-media-cb-preview-cp1-r2 \
     20260813T184753CST-media-e2e-b4-label-guard-r2
   ```

9. 新发布首次门禁通过后，在发布锁内原子切换到固定旧发布，核对活动链接、旧清单、旧入口磁盘与 Nginx 内容校验值、后端发布进程及健康端点。随后在发布锁内原子恢复新发布，再次运行生产门禁并核对新入口和全部清单文件的 Nginx 内容校验值。最终活动链接必须指向新发布。
10. 如果部署后任一步失败，必须在发布锁内把活动链接恢复到固定旧发布并完成旧入口和后端健康读回；不得删除已经创建的新发布。成功路径结束前必须清除隔离目录，确认基础源提交、状态摘要和固定输入文件清单摘要未变化，旧发布仍存在且保持不可变。
