## 实施要求

1. 重新计算三棵工作树的状态摘要与基础源内容摘要，匹配固定身份后才开始。
2. 用 `mktemp -d` 创建隔离目录，从基础源快照复制源文件，排除 `.git`、`node_modules` 和 `dist-media`，并只读复用基础源的 `node_modules`。
3. 只在隔离副本中完成以下一致性修改：
   - 将 `src/media` 中用户可见的旧“赛道与博主”名称统一为“账号与赛道”。
   - 将个人 Web 的 `track` 任务层标签从“赛道”改为“账号与赛道”，机构飞书的“赛道管理”保持不变。
   - 同步 `checkMediaRoleIa.ts` 和 `checkMediaLanguageCatalog.ts` 的个人 Web 预期。
   - 强化 `checkMediaReleaseLabels.ts`：构建产物必须包含所有当前导航标签，并按生产门禁的精确引号/反引号/HTML 文本语义拒绝退役标签；不能删除或弱化现有计费和平台图标断言。
4. 先运行 `npm run qa:media-role-ia`、`npx tsx scripts/qa/checkMediaLanguageCatalog.ts`，再运行 `npm run build:media`。构建必须使用 `vite.media.config.ts`，产物入口资源必须以 `/openclaw/media/` 为基础路径。
5. 构建后确认“账号与赛道”存在，退役的“赛道与博主”和其他生产门禁退役精确标签不存在；确认 `index.html`、`login.html`、`register.html` 与哈希资源均存在。
6. 在 `dist-media` 中生成不含秘密和退役文案的 `.source-snapshot.json` 与 `.source-to-artifact.json`，至少记录基础源提交、基础源状态/内容摘要、补丁后源文件哈希列表摘要、构建命令、构建时间、新前端发布和固定后端发布。
7. 使用 `sudo -n /usr/local/sbin/deploy-openclaw-media-locked DIST_MEDIA BACKEND_RELEASE RELEASE_ID` 创建新不可变发布。若部署或门禁失败，必须原子恢复旧活动链接并核对旧页面和后端健康；不得删除失败的新发布。
8. 新发布首次门禁通过后，执行一次有界回退演练：原子切换到固定旧发布，核对活动链接、旧 `index.html` 的服务端内容校验值和后端健康；随后原子恢复新发布，再次运行生产门禁并核对新 `index.html` 服务端内容校验值。最终活动链接必须是新发布。
9. 重新计算三棵工作树状态摘要，必须与实施前一致；清除隔离构建目录。旧发布必须继续存在且保持不可变。
